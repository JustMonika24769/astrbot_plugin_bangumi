# 全项目审查记录

审查范围：插件入口、全部 `src/` Python 模块与卡片模板、测试、配置、依赖、CI、预览和打包脚本、README 与历史变更记录。运行数据未修改。以下分为已确认修复与需要产品/维护策略决定的事项；不将静态审查当作不存在其他问题的保证。

## 已修复

| 问题 | 修复结果 | 主要位置 |
| --- | --- | --- |
| 数字候选回复未核对用户和会话 | 只处理发起用户在原会话中的 ASCII 数字回复 | `main.py::_NumericSelectionFilter` |
| 搜索分页参数放在请求体、v0 排名读取位置错误 | 分页放入 query；优先读取 `rating.rank`，兼容旧 Calendar 字段 | `src/bangumi_client.py` |
| 默认搜索数量固定为 3，忽略配置默认值 | 使用 `search_limit` 作为未指定数量时的默认值 | `main.py` |
| 准确订阅 ID 或名称仍混入模糊候选 | 数字 ID 只精确匹配，完整名称优先返回 | `src/db/repository.py::find_subscription` |
| 日历缓存跨 CST 午夜保留昨天的今日标记 | 缓存按星期分开；今日卡片日期统一 CST | `src/bangumi_client.py::get_calendar`、`main.py::today` |
| 剧集后续分页格式异常被当作正常结束并缓存 | 抛出客户端错误，不写入不完整结果缓存 | `src/bangumi_client.py::get_episodes` |
| 缓存无上限，未再次访问的过期封面长期占内存 | 写入时清理过期项，限制为 256 项并按最近访问淘汰 | `src/bangumi_client.py` |
| 订阅列表为了封面额外获取条目详情 | 直接使用已存条目 ID 下载封面，减少限流请求 | `main.py::_embed_subscription_covers` |
| 新会话订阅未采用数据库中的人工放送时间 | 已存时间优先于 bgmlist 默认值，用于计算订阅基线 | `src/tracking.py::subscribe` |
| 初始化中途失败不清理，卸载未释放连接池 | 失败时清理；卸载关闭 HTTP 和数据库，撤销就绪状态 | `main.py`、`src/db/repository.py` |
| 数据库路径只有文件名时初始化失败 | 创建绝对路径的父目录，并统一包装初始化错误 | `src/db/repository.py` |
| T2I 返回不存在的路径仍按成功处理 | 校验文件存在，触发既有文字降级路径 | `src/card_renderer.py` |
| 部分外部模板字段未显式转义 | 日期、平台、星期、时长等字段统一转义，避免依赖服务默认设置 | `src/templates/cards/` |
| 翻译 completion 为 null/非字符串时抛异常 | 视为空响应并保留原文 | `src/app/summary_translation.py` |
| 数值配置为无穷时未捕获转换异常 | 使用默认值 | `src/plugin_config.py` |
| 元数据 v2.2.0 与 README、UA、测试不同步 | 同步版本与项目链接；版本测试改为跨文件校验 | 配置、文档、`tests/test_manifest.py` |
| CI 未安装测试导入的 AstrBot；依赖主版本无边界 | CI 安装声明支持的 AstrBot；约束 APScheduler 3 与 SQLAlchemy 2 | `.github/workflows/ci.yml`、`requirements.txt` |
| 严格类型检查与格式检查失败 | 补全缓存类型、收窄可空变量；标注框架无类型边界并执行 Ruff 格式化 | Python 源码和测试 |

## 待决定事项

| 编号/优先级 | 现状、影响与证据 | 建议及需要决定的事项 |
| --- | --- | --- |
| R1 / 高 | `/放送时间` 对任何用户开放，但写的是 `bangumi_subjects` 上的全局字段，会影响订阅同一条目的其他群。`main.py::broadcast_time`、`src/db/models.py`。 | 选择仅管理员可修改全局时间，或迁移为每个会话单独覆盖。后者涉及模型、迁移与播出判定，不直接替你选择。 |
| R2 / 高 | “清空”写入 null，`apply_broadcast_schedules` 次日又会补回；自动导入和人工输入共用字段，已有非空的自动时间也不会随上游更正。 | 增加来源/人工覆盖/禁用自动填充状态，明确清空是临时操作还是持续覆盖；需兼容迁移。 |
| R3 / 中 | `get_latest_aired_episode` 当天无放送时间时要求有评论，冷门剧可能延迟到次日；有时间时只比较当日时刻，跨午夜的日本日期与 CST 日期不一定一致。 | 决定继续保守判定，还是引入明确的播出时区、延迟容忍和按每集时间计算的策略。需要真实跨日样本验证。 |
| R4 / 中 | `Episode.number`/`sort` 为 int，`safe_int` 会截掉 API 小数排序（如 12.5）。通知基线也以整数集数为单位。 | 先确定是否支持普通类型中的小数集、总集篇、重编号；若支持，改用 episode ID 或精确排序作为进度，需数据迁移。 |
| R5 / 中 | `proxy_url` 接受任意协议，配置测试还接受 `socks5://`，请求使用 aiohttp 的 `proxy=`，未配置 SOCKS connector。 | 选择明确只支持 HTTP/HTTPS 代理并验证配置，或引入 SOCKS connector 与对应依赖/测试；不要将现有字符串解析测试视为 SOCKS 连接成功证据。 |
| R6 / 中 | LLM 翻译没有插件级超时，在逐条目更新检查持锁期间等待；模型挂起可能阻塞后续通知。重试通知也会重新翻译。 | 选择可配置的翻译超时和按文本/模型缓存；确定超时后发送原文是否符合预期。 |
| R7 / 中 | 所有 SQLAlchemy/SQLite 操作同步运行在异步入口；模糊查询扫描本会话所有订阅并重复计算相似度。当前没有规模/延迟基准。 | 先给出实际订阅规模并测量。规模较大时，再采用线程隔离或异步存储，并增加 `subscriptions.subject_id` 索引；不凭静态代码直接改写存储层。 |
| R8 / 中 | 同一条目的同时查询未合并请求；更新检查每轮刷新全部条目和全部剧集，包括完结条目。单实例限流会放大耗时。 | 决定完结条目是否暂停检查、详情刷新频率，以及是否合并相同的正在执行请求。自动停检可能错过补集，需先确定业务规则。 |
| R9 / 中 | 消息发送成功与数据库标记是两个操作。若成功发送后写库失败/进程退出，下一轮会重复发送。 | 确定是否需要更强的投递保证；可记录投递任务与状态，但没有平台幂等键时不能承诺严格只发送一次。 |
| R10 / 低 | `_parse_broadcast_time`、`set_broadcast_time`、`SchedulerManager.cancel_job` 没有生产内部调用；`raw_config` 只有赋值。另有会话类型规范化映射在两处重复。 | 确认没有外部调用者后可删兼容接口和未用属性；会话规范化可另做共享函数重构。此次保留兼容接口。 |
| R11 / 低 | `/放送时间` 仍依赖三个位置参数，不能像搜索一样可靠保留含空格的名称；搜索尾部 1–10 的数字会被解释为结果数量，可能与番名冲突。 | 决定是否支持引号或显式数量参数。当前可使用准确 ID 避免歧义。 |
| R12 / 低 | 预览脚本遗漏 help 卡片；打包脚本纳入全部 Git 已跟踪与未忽略文件，包含开发文件，也可能纳入不该发布的未跟踪文件。 | 决定是否增加 help 预览、按运行文件白名单打包；后者会改变当前发布内容，且本环境没有运行 Windows/7-Zip 验证。 |
| R13 / 低 | 调度器使用 pytz，其他模块混用 UTC+8 固定偏移和服务器本地 `datetime.now()`；数据库检查时间没有时区。Ruff target 是 py311，CI/mypy 是 3.12。 | 确定时间存储及兼容底线后统一为标准库时区和明确时间格式；历史数据库时间不能直接猜测时区转换。 |
| R14 / 中 | 卸载未主动结束当前候选等待；APScheduler 的关闭是异步调度取消，手动命令任务也不由插件统一跟踪。 | 如需保证热重载期间无旧回调，应跟踪并取消本插件等待及在途任务，增加真实框架下的重载集成测试。此次只修复可明确验证的资源释放。 |
